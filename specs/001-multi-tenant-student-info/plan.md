## Summary

Establish the complete foundational data and API layer for Education Flow: a multi-tenant school management system serving Pakistani schools. This covers schema-per-tenant isolation using PostgreSQL schemas, all staff account onboarding, school academic structure configuration (classes, sections, subjects), and student record management with Pakistani-specific validation (B-Form, CNIC, phone format, address, guardian with relationship).

The backend is a NestJS mono-module app that will be expanded into a fully modular, tenant-aware architecture. A `TenantMiddleware` resolves the school from the subdomain on every request and attaches a tenant-scoped `PrismaClient`. JWT tokens carry `role` + `tenantId` claims, and a `RolesGuard` enforces permissions on every endpoint. The frontend (Next.js) adds the login screen and the key student/class/staff management pages.

## Implementation Phases

### Phase A — Backend Infrastructure

| Step | What | Details |
|---|---|---|
| A1 | Prisma schema | Define public schema (Tenant model); define tenant schema (StaffUser, Class, Section, Subject, Student, Guardian, enums) |
| A2 | Migration | `prisma migrate dev --name init_tenant_schema`; add raw partial index for B-Form |
| A3 | PrismaModule | `GlobalPrismaService` (public schema) + `TenantPrismaService` (factory, cached by schema name) |
| A4 | TenantMiddleware | Subdomain extraction → `public.tenants` lookup → attach `tenantId` + `schemaName` to request |
| A5 | Auth module | JWT strategy, local strategy, login, refresh, change-password endpoints |
| A6 | Common | `RolesGuard`, `JwtAuthGuard`, `@Roles()` decorator, `ResponseInterceptor`, `HttpExceptionFilter` |
| A7 | Staff module | `POST /staff`, `GET /staff`, `DELETE /staff/:id` with role enforcement |
| A8 | Academics module | Classes, Sections, Subjects CRUD with safety guards (no delete if students/marks linked) |
| A9 | Students module | Student CRUD with B-Form uniqueness check (active records only), guardian create/update, role-filtered list |
| A10 | Unit tests | `StaffService`, `AcademicsService`, `StudentsService` — key business logic paths |

### Phase B — Shared Types

| Step | What | Details |
|---|---|---|
| B1 | Enums | `StaffRole`, `Gender`, `Religion`, `Relationship` enums in `shared-types` |
| B2 | Interfaces | `StudentDto`, `StaffUserDto`, `ClassDto`, `SectionDto`, `SubjectDto`, `GuardianDto` |

### Phase C — Frontend

| Step | What | Details |
|---|---|---|
| C1 | Install deps | `shadcn/ui` init, `@tanstack/react-query`, `react-hook-form`, `zod`, `axios` |
| C2 | API client | Axios instance; attach Bearer token from cookie; handle 401 → redirect to login |
| C3 | Login page | shadcn Form + Zod, CNIC formatted input, forced password change redirect |

| C7 | Student profile | View + edit mode; role guards hide edit controls for Teacher |
| C8 | Classes/Sections/Subjects config | Inline add/remove UI |
| C9 | Staff directory | Table with Clerk view (no delete button) + Principal delete action |

### E2E Flow Test (Manual — 5 steps)

**Prerequisites**: `npm run db:up && npm run start:dev` running.

1. **Tenant provision**: POST to `localhost:3001/api` (with `X-Tenant-ID: test-school`) — confirm school schema created.
2. **Login as Principal**: `POST /api/auth/login` with CNIC + temp password → forced password change → get access token.
3. **Create structure**: Create a Class, add a Section, add Subjects — verify they appear in `GET /api/classes`.
4. **Admit student**: `POST /api/students` with full payload including guardian → verify created.
5. **Tenant isolation**: Repeat step 4 with `X-Tenant-ID: school-b` → confirm school-a student does NOT appear in school-b `GET /api/students`.

### Pakistani Validation Test

Using the admission form or Postman, verify rejection of:
- B-Form `1234-123-1` → `400` with field error
- Phone `03211234` (too short) → `400`
- CNIC `12345-123-1` → `400`
- Valid formats → `201` accepted
